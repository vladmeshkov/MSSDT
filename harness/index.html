04 — Теория: что такое harness

Harness — программа, которая управляет моделью

  • отправляет модели задачу
  • даёт ей инструменты: почту, файлы, поиск
  • хранит память о прошлой работе
  • проверяет результат
  • следит за правилами и доступами

по-русски — «обвязка», дословно «упряжь»

«Если ты не модель — ты харнесс»Vivek Trivedy, LangChain
Для маркетологаМодель — товар. Harness — то, что отличает один продукт от другого

06 — Пример: ИИ разбирает почту
Человек

только читает и пишет текст. С почтой она не общается напрямую

07 — Пример: цикл агента в коде
agent_loop.py — схема, не реальный код
def run_agent(task):
    history = [task]
    while True:
        prompt = build_prompt(history)   # 1) собрать запрос
        reply  = llm(prompt)             # 2) спросить модель
        if not reply.tool_calls:         # 3) вызовов нет →
            return reply.text          #    это ответ
        for call in reply.tool_calls:
            check_permissions(call)    # 4) права
            result = run_tool(call)      # 5) выполнить
            history.append(result)      #    и запомнить
  • 1
    build_promptсистема + инструменты + память + история + запрос
  • 2
    llmвызов модели: текст и/или просьба о вызове инструмента
  • 3
    tool_callsнет просьб — это финальный ответ, выходим из цикла
  • 4
    check_permissionsсистема решает, разрешено ли действие
  • 5
    run_toolвыполнить и вернуть результат модели; ошибка — тоже результат

Когда цикл останавливается

ответ без вызововлимит ходовбюджет токеновсработал tripwireчеловек прервалsafety refusal

10 — Проблема №2: ошибки

Беда №2: ошибки копятся

Даже при 99% успеха на шаге дело из 10 шагов заканчивается без ошибок лишь в ~90% случаев. Из 50 шагов — в 60%.

0,99¹⁰ ≈ 0,904
0,99²⁰ ≈ 0,818
0,99⁵⁰ ≈ 0,605

Поэтому harness ловит сбой, возвращает его модели как результат и ограничивает число повторов (в Stripe — не больше двух).

16 — Итоги
1

Модель — товар. Harness — продукт.

Модели доступны всем; отличие продукта живёт в программе вокруг модели.

2

Harness — это конкретно: цикл, инструменты, память, проверки, права.

Не магия, а программа, которую можно разобрать по частям и сравнить.

3

Сравнивайте продукты по четырём вопросам, а не по названию модели.

Память · проверка · права · поведение при ошибке.
